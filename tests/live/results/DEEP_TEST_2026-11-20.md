nondeterministically refuses off-topic prompts with a canned Chinese
intro ("my role is to help you write/modify/understand code…") instead
of answering. Every "lacks 'Paris'" failure below is that refusal:

11.7 s, 5 B). Soak: 2/5 Paris in part 2. This is server/Gem
behaviour, not a CLI regression — but it makes the Paris-needle
checks flaky and they should be re-pointed at a coding prompt.

| `cli-show-thoughts-plain-flash` (control b) | **PASS** | Plain flash + `--show-thoughts`: pointer has no `thoughts`, stderr carries "No thoughts returned…" — the designed behaviour for a non-thinking model. |

### Why there is no trace: the server sends an empty slot

A raw library probe (no browser, WebAPI `generate_content`, direct,
flash+extended, sqrt(2) proof — 992-char answer) spied on
`GeminiClient._parse_candidate`: the candidate has 38 slots with
index 37 present but **`candidate_data[37] == []`** — the server
sends no thinking trace for chat turns on this account. The library
parses the right slot; the slot is empty. Corroborated by
`gemini.py` (same library, same source): direct
`flash+extended` and `pro+extended` sqrt(2) proofs (both 1,216 B,
real reasoning) both log "No thoughts returned…", pointer has no
`thoughts` field. Files:
`tests/live/results/gemini_show_thoughts_direct_2026-11-20.md`,
`gemini_show_thoughts_pro_2026-11-20.md`.

So the extraction code itself is verified (offline suite 51/51,
fake-response end-to-end in the HEAD commit, and control (b)
behaving exactly as designed), but **a non-empty live trace cannot
currently be produced on this account** — `cli-show-thoughts` is
BLOCKED by the server withholding the trace, not by the CLI. The
matrix case now records that honestly (it cannot pass until the
server populates slot 37 for chat turns). Deep-research turns were
the one path the CLI notes as "often" carrying thoughts, but DR
itself did not complete today (§5), so that leg is untested live.

### Side finding: gem-cli.py cannot run a bare direct prompt

`gem-cli.py --show-thoughts -m flash --thinking extended -t 180 -o
… "Prove sqrt(2)…"` fails `NO_URL`: the sentence-like first
positional is merged back into the prompt (correct), but then the
`NO_URL` guard fires because no Gem was given. The AGENTS.md claim
that "a bare prompt without a Gem runs direct" is false for
gem-cli.py (gemini.py handles direct prompts fine — part 1 `direct`
PASS). Pre-existing, out of scope for this run, flagged here.
