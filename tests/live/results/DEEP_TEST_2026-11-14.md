## Fixes made (all live-verified)

1. `-g <gem> <prompt>` → `NO_PROMPT` (gemini.py): positional prompt words
   dumped into `args.url` were never merged back. Verified quoted and
   unquoted (`Double the number 21 ...` → `42`).
2. `--raw` leaked the no-live-session warning to stderr (gemini.py):
   module-level `_RAW_STDERR` flag; same gate for the BrowserBatchRPC
   notice and gem-cli.py's `--init` message.
3. `--list-chats` printed `ok:true, []`: root cause is Gemini Activity
   off (BardErrorInfo 1041), not a degraded session. Now fails
   `LIST_CHATS_FAILED` with the server message.
4. gem-cli.py `--img` / `--deep-research` / `--resume` without a Gem
   failed `NO_URL` / `BAD_URL`: now run direct (gem-less); bare prompt
   merges back into `args.prompt`.
5. gem-cli.py DR crashed on `on_status` (gemini-webapi 2.1.1's
   `wait_for_deep_research` has no such kwarg): guarded by `_supports`.
6. Plan-creation retries (both CLIs): the plan endpoint is flaky on a
   degraded session (~3/5 attempts return empty or a refusal); retry up
   to 3 times, 15s apart.

## Server behaviours documented

- `--delete-chat` removes the history entry; the conversation object
  stays readable by `--read-chat <cid>`.
- `--browser <name>` falls back to the cached credential when that
  browser has no cookies (by design).
- The `coding-partner` Gem refuses non-coding questions by persona
  (e.g. arithmetic, capitals) — a Gem artifact, not a CLI failure.
